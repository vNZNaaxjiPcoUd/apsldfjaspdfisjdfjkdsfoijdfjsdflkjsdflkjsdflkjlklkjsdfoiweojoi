全程於瀏覽器本地運算，體驗「金鑰留存在 URL # 後方、伺服器僅見盲化密文」的架構原理

零知識資料流向與節點可見範圍架構圖

RFC 3986：瀏覽器發送 HTTP 請求時會自動截斷 # Fragment
1. 傳送端瀏覽器（本地） 全權可見

本地生成 256-bit Key 與 12B IV，加密產出密文後，僅上傳密文至伺服器，並將金鑰拼接於網址 # 後方。

2. 雲端伺服器（盲化儲存） 無金鑰 · 無法解密

僅儲存 [IV + Ciphertext + AuthTag]。HTTPS 請求不包含 # 後方內容，伺服器日誌與資料庫皆無明文與金鑰。

3. 接收端瀏覽器（本地） 本地還原

向伺服器取得密文封包，切出前 12 bytes IV，並從本地 location.hash 提取金鑰執行 AES-GCM 驗證與解密。

AES-GCM 的 16-byte 驗證標籤（Auth Tag）比對失敗！這代表密文、IV 在傳輸或儲存過程中曾遭到竄改，或者您輸入的金鑰不正確。瀏覽器已拒絕輸出任何未經授權的資料。

本頁面完全使用瀏覽器原生 window.crypto.subtle（AES-GCM）與 crypto.getRandomValues 運算，無任何資料傳送至外部伺服器。
